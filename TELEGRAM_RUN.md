# Запуск двух демонстрационных ботов

`telegram_bots.py` содержит два сценария для настоящего Telegram Bot API: LeadBot собирает бриф, EventBot собирает параметры регистрации на вымышленное событие. Оба отвечают только инициатору в личном чате. Браузерные страницы `leadbot.html` и `eventbot.html` доступны отдельно, без токенов.

Нужны Python 3.10 или новее, интернет и отдельный бот, созданный владельцем через BotFather. Зависимости устанавливать не требуется. **На GitHub Pages Python-процесс не запускается.** Для постоянной работы нужен включённый компьютер или сервер. Тесты сценариев выполнены без сети; запуск с настоящим токеном ещё не проверен.

Задайте `BOT_TOKEN` только в приватном окружении запуска. Не вставляйте его в исходники, README, скриншоты, публичную историю команд или GitHub. `.env` исключён из репозитория, однако этот скрипт сам не читает `.env`.

Выберите сценарий через `BOT_MODE=lead` либо `BOT_MODE=event`, затем запустите:

```text
python telegram_bots.py
```

Для одновременной работы двух ботов нужны два отдельных токена и два процесса. Используйте новые демонстрационные боты. Скрипт проверяет наличие webhook и останавливается, если обнаружит существующую настройку; он не удаляет webhook и не меняет разрешения.

Команды: `/start` — новый диалог, `/cancel` — отмена. В анкете есть возврат на предыдущий шаг и пропуск деталей. Старые кнопки не меняют текущую анкету. Ответы хранятся только в памяти до завершения, отмены, перезапуска процесса или истечения 30 минут. Очистка истёкших диалогов происходит при следующем входящем обновлении. Тексты сообщений не пишутся в журнал. Хранение самих сообщений в Telegram определяется Telegram.

В этой версии нет CRM, передачи заявок менеджеру, оплаты, реальной регистрации на событие или выдачи билета. EventBot показывает учебную сводку. Для рабочего внедрения отдельно согласуются хранение, доставка заявки, правила обработки данных и размещение.

Реализация использует [официальный Telegram Bot API](https://core.telegram.org/bots/api): `getUpdates`, `sendMessage`, `answerCallbackQuery` и inline-кнопки.

Локальные проверки сценариев и восстановления после временного сбоя отправки:

```text
python test_telegram_bots.py
```
# Защита обработчика

Обновление от 7 октября 2026: обработчик проверяет структуру обновлений и принадлежность личного чата, принимает только известные варианты кнопок, ограничивает поток сообщений. Превышение 12 обновлений на чат за 10 секунд или 20 глобально за секунду игнорируется. После короткой паузы можно продолжить; /start запускает сценарий заново.

Сессии очищаются в цикле опроса примерно через 30 минут неактивности. /cancel удаляет ответы даже при недоступности подтверждения Telegram. Сетевой повтор не восстанавливает просроченные ответы. Проверки: `python test_telegram_bots.py`. Область аудита и ограничения описаны в [SECURITY.md](SECURITY.md).

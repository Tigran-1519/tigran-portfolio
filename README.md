# Портфолио Тиграна Шогояна

Статическое портфолио на русском языке: сайты, web-сервисы и сценарии ботов. Пять работающих браузерных демонстраций и материалы собственных проектов. Визуальный стиль: графит, почти белый фон, кобальтовый акцент и крупная типографика. Готов к размещению на GitHub Pages или любом статическом хостинге. Установка зависимостей и сборка не требуются.

## Локальный запуск

Откройте терминал в этой папке и выполните:

```text
python -m http.server 8000
```

Затем откройте `http://localhost:8000/`. Если порт занят, замените `8000` другим свободным портом. Остановить сервер можно сочетанием Ctrl+C.

Основная страница также открывается непосредственно из `index.html`. Для проверки поведения буфера обмена предпочтителен локальный сервер. Копирование работает на HTTPS или localhost; если браузер не разрешает доступ к буферу, демо выделяет текст и предлагает скопировать его вручную.

## Что работает

- `index.html` — главная страница, пять крупных кейсов и реальные превью страниц в iframe. Превью загружаются лениво, скрыты от вспомогательных технологий и клавиатуры; у каждого проекта есть отдельная ссылка «Открыть». Нумерованный навигатор позволяет перейти сразу к нужному кейсу; на телефоне список прокручивается горизонтально. Каждый кейс объясняет задачу и содержит конкретный сценарий «Попробуйте» с ожидаемым результатом. Мобильные тексты и ссылки открытия увеличены для удобства чтения и касания. В разделе #request работает форма заявки: название, описание до 6 000 символов, необязательное имя/ФИО и обязательный контакт (телефон, Telegram или email). Кнопка «Отправить задачу» передаёт данные серверному обработчику, который доставляет их владельцу в Telegram. Успех показывается только после подтверждения доставки; при ошибке текст остаётся в форме.
- `furniture.html` — адаптивный лендинг вымышленной мастерской «Тихий дом». Выбор изделия, отделки, размеров и помещения; условная иллюстрация; проверка числовых диапазонов; генерация структурированного текста заявки; копирование и сброс. Изменение параметров скрывает старую заявку до повторной генерации.
- `leadbot.html` — браузерный симулятор сценария бота. Три шага, разные цели для разных задач, итоговый бриф, копирование и перезапуск диалога.
- `desk.html` — BriefDesk, кабинет заявок: поиск, фильтрация, статусы, карточка заявки, импорт/экспорт JSON и локальное сохранение.
- `slotly.html` — Slotly, выбор услуги, даты и времени, локальная сводка записи и сброс. Без связи с реальным календарём.
- `eventbot.html` — EventBot, браузерный сценарий выбора формата и сессии, сводка участия, копирование и перезапуск. Без реального билета или регистрации.
- Семантическая разметка, подписанные поля, управление с клавиатуры, видимый фокус, сообщения о результате и поддержка `prefers-reduced-motion`.

## Ограничения

Демонстрационные страницы работают локально. Только форма #request на главной отправляет заявку через отдельный серверный обработчик. Аналитики и платежей нет. BriefDesk и Slotly сохраняют свои демонстрационные данные в localStorage этого браузера; они не передаются на сервер. Остальные сценарии работают только в текущей вкладке. В приватном режиме или при запрете хранилища локальное сохранение может быть недоступно. Форма не сохраняет черновик после перезагрузки. Её сервер принимает запросы только с публичного origin портфолио; отправка из локального preview по умолчанию отклоняется. В мебельном демо не рассчитываются цена, конструкция или производственные допуски. Иллюстрации мебели условные, не масштабируются по введённым размерам.

MemoBook доступен отдельной страницей memobook.html. Новый браузерный LeadBot — отдельный демонстрационный сценарий собственного проекта. LeadHunter описан как собственный инструмент обработки открытых данных и CSV; онлайн-версия и исходники этого проекта в данную папку не включены. Никакие кейсы не заявлены как работы для вымышленных заказчиков.

Состав этапа, стоимость, сроки и порядок оплаты обсуждаются отдельно. Работа с Codex честно указана в процессе на главной странице.

## Отдельный запуск ботов в Telegram

В репозитории также есть `telegram_bots.py` — отдельный Python runner для двух сценариев, LeadBot и EventBot. Он запускается локально по [TELEGRAM_RUN.md](TELEGRAM_RUN.md), требует Python 3.10+ и собственного `BOT_TOKEN` в окружении. Используется стандартная библиотека, установка пакетов не нужна. Есть inline-кнопки, возврат, отмена и временное состояние диалогов; для работы нужен запущенный процесс.

Это отличается от браузерных симуляторов: демонстрации LeadBot и EventBot остаются отдельными от бота приёма заявок. Python runner работает с Telegram API после самостоятельной настройки. Реальные токены и запуск в Telegram не проверялись; боты не заявлены как уже работающие в Telegram. Токены, личные данные и рабочие `.env` не входят в публикацию.

## Результат и приёмка

Главная связывает демонстрации с тремя типами задач: лендинг, бот для заявки и рабочий интерфейс. Раздел «Что получаете. Как проверяете» описывает возможный состав и проверку первой работы. Цена, сроки и подключение сервисов согласуются отдельно. Форма заявки доставляет имя, контакт и задачу в бот «Шогоян - Разработка»; рядом сохранена ссылка для прямой связи. Главная адаптирована для чтения на телефоне: основной текст увеличен, у BriefDesk последовательная вертикальная композиция.

## Доставка заявок

Обработчик: https://tigran-portfolio-requests.tigran-shogoyan.chatgpt.site/api/requests . Токен и ID получателя хранятся только на сервере. Длинные заявки доставляются текстовым файлом. Ограничения: 4 заявки с IP за 15 минут и 50 в час суммарно, проверка полей, защита от повторной отправки по UUID. Сбой связи не считается успешной доставкой. Имя и контакт используются для обсуждения задачи.
